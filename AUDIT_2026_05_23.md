**Verdict: BIJOTEL ships 0 known vulnerabilities.** The 4 `pip` CVEs
affect the installer in the user's environment, not BIJOTEL's runtime.

### Secrets in repo

`git ls-files | grep -E "\.env$|\.pypirc|\.key$|\.pem$|_secret$"`
returns **empty**. ``.gitignore`` correctly excludes `.env`, `.env-*`,
`.audit_tmp/`, `node_modules/`, `dashboard_dist/`. No accidental secret
commits across the 12-day history.

### Auth surface

`APIKeyMiddleware` is **opt-in** (no key = open dev mode). When
configured:
* Uses `hmac.compare_digest` (constant-time) — resistant to timing
  attacks.
* Bearer scheme case-insensitive (RFC compliant).
* Empty `BIJOTEL_API_KEY=""` treated as "unset" (misconfig guard).
* Public allow-list: `/`, `/assets/*`, `/health`, `/version`, `/docs`,
  `/redoc`, `/openapi.json`, `/api/health`, `/api/version`.

No CSRF token on POST endpoints — acceptable for token-based bearer
auth (no cookies), but worth noting if a session cookie is ever added.

| #7  | fingerprint | available | available (no sentence-transformers in venv) | available |

| #18 | misalignment | available | available | available |
| D   | containment | available | available | available |
| #3  | energy | planned | planned | planned |
| #9  | consensus | planned | planned | planned |

**Drift:** README has 13 rows, runtime has 14. The missing row is
`merkle_dag` (#2 as a separate sub-layer). README implicitly groups it
under "Content-Addressable + Merkle DAG" in the same row. Recommended
fix: either bump README to 14 OR collapse the runtime to match the
README's grouping. I lean toward bumping README — the runtime split is
the more honest model (DAG can be `available` while CAS is `active`).

**Honest observation:** "active" requires runtime evidence. On a fresh
`pip install`, only 2 layers report active (otel_genai +
provider_protocol). The "6 active" claim in `LAUNCH_CHECKLIST.md` is
true ONLY for the GENA-state snapshot, not for the first user who
installs from PyPI. Worth caveating in docs.
